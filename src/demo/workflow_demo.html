Shape A · Workflow

Gửi một yêu cầu hoàn phí và xem workflow.py xử lý từng bước theo thứ tự cố định. Dữ liệu là kết quả chạy thật trên 14 claim public, không gọi model hay API.

Cách hoạt động của hai phương pháp đọc trước, rồi thử bên dưới

A Workflow: quy trình cố định

Code viết sẵn từng bước theo một thứ tự không đổi, giống phiếu kiểm tra. Mỗi bước chỉ có if/else, không có chỗ nào để "tự chọn" việc tiếp theo.

Đọc claim→Đọc đơn→Tính quote→Host ghi tiền→Kết quả
  • Ưu: dễ đoán, dễ test, ít bước nhất nên rẻ nhất.
  • Hạn chế: cứng. Gặp tình huống mới thì phải sửa code.

Mức tự chủ: thấp nhất. Code quyết cả thứ tự lẫn nội dung.

B Single agent: vòng lặp ReAct

Một agent lặp lại: nhìn kết quả đang có, chọn một tool đọc, đọc kết quả, rồi lặp, tối đa 8 vòng thì chốt. Việc ghi tiền vẫn do code làm sau vòng lặp.

decide→tool đọc→quan sát↻tối đa 8 vòng→Code tính quote→Host ghi tiền→Kết quả
  • Ưu: linh hoạt, tự chọn tool theo tình huống.
  • Hạn chế: tốn thêm vòng, khó đoán hơn. Nếu decide tin chữ trong ticket thì sẽ sai ở bộ hidden.

Mức tự chủ: vừa. Agent chọn tool đọc, nhưng không được chọn số tiền hay ghi ledger.

Điểm giống nhau: tiền do code tính (compute_compensation), ghi tiền chỉ qua host (issue_refund: approval, trần theo đơn, idempotency), luôn truyền quote đầy đủ, trace không chứa dữ liệu nhạy cảm. Điểm khác nhau: ai quyết thứ tự các bước. Ở A là code cố định, ở B là decide chọn trong từng vòng. Trong lab này decide là hàm Python xác định, chưa gọi model thật, nên bản demo cho thấy cách khung chạy chứ chưa cho thấy sự bất định của một LLM.
